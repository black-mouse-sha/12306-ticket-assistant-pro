## ⚠️ 只看域名：必须在 `kyfw.12306.cn` 下，任何页面都行

**规则是按域名，不是按页面。** 只要地址栏开头是 `kyfw.12306.cn` 就能抢：

| 页面 | 地址 | 能抢吗 |
|---|---|---|
| 车票查询（单程） | `kyfw.12306.cn/otn/leftTicket/init` | ✅ |
| **个人中心 / 我的12306** | `kyfw.12306.cn/otn/view/index.html` | ✅ **实测在这儿下出过真订单** |
| 订单中心、候补订单等 | `kyfw.12306.cn/...` | ✅ |
| 首页 / 主页 | `www.12306.cn/index/index.html` | ❌ 下单会被拒 |
| 会员服务 | `www.12306.cn/...` | ❌ |

**为什么**：12306 的「提交订单」接口 `submitOrderRequest` 会检查请求来源。从 `www.12306.cn` 发过去的请求是跨域的，**补不上它要的 Referer**，12306 就返回一张 HTML 错误页。

**实测后果**（2026-10-17 真事）：

| 页面 | 查票 | 抓票 | **下单** |
|---|---|---|---|
| `www.12306.cn`（首页） | ✅ 能 | ✅ 10:45:00 抓到了票 | ❌ **连试 10 次全被拒** |
| `kyfw.12306.cn/otn/view/index.html`（个人中心） | ✅ 能 | ✅ 抓到了票 | ✅ **第 1 次就成功，订单号 EF3524****（已打码）** |

所以：**查票走哪都行，抢票只能在 kyfw 域名下。** v3.3.4 起，在 `www.12306.cn` 上点「开始抢票」会被**直接拒绝**并弹出说明，不会再让你到点才发现。

> 判断方法：看地址栏开头是不是 `kyfw.12306.cn`。

## 安装

**方式 A（推荐，一键安装）**

1. 浏览器安装 **Tampermonkey**（油猴）扩展。
2. 点 **[一键安装脚本](https://black-mouse-sha.github.io/12306-ticket-assistant-pro/12306-ticket-assistant-pro.user.js)**，油猴会弹出安装页 → 点「安装」。
   （打不开的话，从 [GitHub 文件页](https://github.com/black-mouse-sha/12306-ticket-assistant-pro/blob/main/12306-ticket-assistant-pro.user.js) 点「Raw」安装。）
3. 打开 **12306 → 车票 → 单程**（地址应是 `kyfw.12306.cn/otn/leftTicket/init`）。
   面板出现在右上角。
4. 面板标题上的版本号应该是 **v3.3.5**。

**方式 B（手动，适合改代码）**

1. 装 Tampermonkey。
2. 油猴面板 → 「添加新脚本」→ 把 `12306-ticket-assistant-pro.user.js` 的内容整份粘进去 → **Ctrl+S 保存**。
   （也可以把 `.user.js` 文件直接拖进浏览器窗口，油猴会弹安装页。）
3. 打开 `kyfw.12306.cn` 的任意页面，确认面板版本号是 **v3.3.5**。

## 三步用法

**① 条件** —— 填一次，之后自动保存

- **出行日期**：点那行展开日历。**点一下选主日期，再点一次取消它**；**Shift + 点**选一整段（最多选到预售期内）。
  「**清空所有日期**」一键清空（预约不受影响）—— 想只留预约时最快。
- **从哪到哪**：写中文站名，比如 `杭州东` → `瑞金`。**写全**：写「杭州」是杭州站，不是杭州东。
- **席别**：点选的顺序 = 优先顺序（脚本按这个顺序挑第一个有票的）。至少勾一个。
- **车次**：留空 = 不限车次。填了就只有这些车次算数。
- **谁坐**：点姓名选中；点右边的「学」标记学生票。
- **高级设置**：车厢图选座（靠窗/过道/挨着，也能直接在图上点座位号）、接受同城其它车站、买长乘短、自动候补、报警、声音、静音车厢。

**② 方案** —— 点「下一步」，脚本真去查一遍

查回来的每一条方案都带：车次、时间、**票价**、席别余票、**起售时间**。你可以：

- 勾选 / 取消（不勾 = 不抢这条）
- 点右上角 **✕** 删掉（重新查也不会再出现；顶上有「恢复已删」）
- 按住 **⠿** 拖动排序（只在同一个「开火时刻」组内拖）
- 上面三个筛选：不勾哪一类 = 不抢那一类

列表按 **开火时刻** 分组。起售时间不同的票不在同一时刻竞争，所以「从上到下」只在组内生效。

**③ 抢票** —— 点「开始抢票」

严格按你排的顺序择优：整程（直达 / 买长乘短）到手就**全停**并跳支付页；中转第 1 段到手只是**半步**，脚本继续盯第 2 段，同时催你先付款。

## 第一次用，建议这样测（安全）

1. **先只点「下一步」**。这一步纯粹是查票，**不会下任何单**，零风险。重点看：
   - 列出来的方案对不对、有没有它自己乱挑的换乘站；
   - 每条方案上的「起售时间」跟你了解的对不对得上。
2. 第二步再点「开始抢票」，**挑一趟现在就没票的车次**试。脚本会一直显示「捡漏中 · 无票」，不会真下单——你能完整看到轮询、开火、退避的行为。
3. **跨时段接力（中转两段起售时间差很远）第一次别在要紧的时候试**。它会先买下第 1 段（真下单、真要付款），再等第 2 段。

## 点「下一步」没反应？按按钮上的字对症下药

按钮**禁用时会把原因写在自己身上**（比如 `还差：加载乘车人`），看一眼就知道：

| 按钮上写的是 | 原因 | 怎么办 |
|---|---|---|
| `还差：加载乘车人` | 乘车人列表没拿到 | 看日志最后一行。若是 `Failed to fetch` / 超时 → 跨域被拦（见下）；若是「请求成功了，但没返回乘车人」→ **没登录**，登录后点「重新加载」 |
| `还差：勾乘车人` | 列表拿到了，但你一个都没选 | 点一下乘车人的**名字**（变蓝才是选中）。点右边的「学」是标记学生票，不会选中 |
| `还差：选席别` | 一个席别都没勾 | 勾至少一个 |
| `还差：填站点` | 出发站或到达站是空的 | 填中文站名，写全（「杭州东」不是「杭州」） |
| 按钮是亮的，点了日志刷 `查询没成功` | 12306 拒了查询 | 多半在限流，等十几秒再点一次 |
| 按钮一直显示 `正在查询 12306…` | 请求挂着没回来 | v3.0.1 起不会超过几秒：跨域会直接走油猴通道，同源有独立看门狗。若仍然卡住，说明装的还是旧版 |
| **列出来一条都没有，日志说「查到 N 趟有票的车，但区间是…」** | **站名写的是城市，车实际走同城另一个站** | 改成精确站名（上海→杭州 要写 上海虹桥→杭州东），或打开「接受同城其它车站」 |
| **日志说「中转：…是当天出发」** | **12306 不给当天出发的接续换乘方案** | 把日期选到**明天以后**。见下 |

### 中转必须选「明天以后」的日期

这条是实测出来的，很容易踩：**12306 的接续换乘对「当天出发」一律返回"没有查询到中转方案"**。同一个接口，把日期换成明天，方案就正常返回。

所以面板默认选「今天」时，**中转永远是 0 条**——不是脚本坏了（这种情况脚本现在会弹横幅告诉你）。
只想抢今天的话，直达和买长乘短照常用，不受影响。

### 换乘等待时间

脚本默认只接受**等待 ≥ 10 分钟**的换乘方案。两段是**同一趟车**（同车换乘、换个座位而已）时会自动放宽——那种方案根本不用下车，等待时间再短也没关系，卡片上会写「同车换乘（不用下车）」。

另外：日志默认**收起**，但**一报错就自动展开**（右下角「运行日志 ▴」）。遇到任何怪事，先看那块。

### 关于「跨域」这件事

12306 的接口全在 `kyfw.12306.cn`。你人在别的 12306 页面上（比如 `www.12306.cn` 的个人中心）时，那就是跨域：

- 脚本带了 `X-Requested-With` 这类自定义头，浏览器会**先发一个 OPTIONS 预检**；
- **12306 的边缘节点对预检经常不回**，浏览器就一直挂着——fetch 既不成功、也不报错；
- 所以"等 fetch 抛错再兜底"是等不到的，表现就是「一直在查询」「乘车人加载不出来」。

v3.0.1 的处理：**跨域请求直接走油猴通道**（`GM_xmlhttpRequest` 由扩展在后台发出，没有预检这回事），同源请求仍然用页面 fetch。

> **最稳的用法还是把面板开在 `kyfw.12306.cn` 的车票查询页上**——那样全部请求都是同源，
> 走的是 v2.1.17 已经跑通的那条路，请求头和 Referer 与浏览器真实操作完全一致。
> 主页/会员中心上能用，但下单接口对请求头的挑剔程度我没法在这里替你验证。

### 预约抢票（抢预售期外、还没开售的票）

**预售期只有 15 天**，所以「提前半个月抢票」的真实含义是：**在开售那一天的那个时刻抢**。

日历上**灰底的日期**就是预售期外的（12306 此刻查不到任何车次）。**点一下它**，就设成预约：

1. 会弹出一行「预约抢票：XXXX-XX-XX 的票」
2. **开火时刻自动填好**（用记住的出发站起售时刻推算；规则是「出行日期 − 14 天」）
3. 想改就改时间框，或者点「用起售时刻」重新填
4. 回到第 ① 步点「下一步」→ 方案列表里会出现一条**预约方案**（橙色「预约」标签）

**设预约会清掉原来的出行日期** —— 因为「预约」的意思是"我要的就是那一天"。日历收起后那行会直接显示
`10-31 预约 ＋预约 10-31`，展开则写 `只抢预约那天：10-31`，一眼能看出当前到底在抢什么。
**两个都想要**（比如今天抢 10-30、同时预约 10-31），再点一次那两个日期即可，两行会并列显示。

> ⚠️ **预约只抢直达**（一张票、不下车），**不含中转 / 买长乘短**。
> 中转要两段都可售才查得到、买长乘短要核对经停站 —— 开售那一秒都来不及做。
>
> **想要中转/买长乘短也一起抢**：等那个日期**进了预售期**之后，在**开售前十几分钟**用正常流程 ——
> 回第 ① 步点一次「下一步」，那时直达 / 买长乘短 / 中转会全列出来，各自标好开火时刻。
> 这比预约更强，只是需要你在场。

它的意思是：**这个日期现在还查不到车次，到点脚本自己去查票、再按你的席别优先顺序抢。**

> 两种做法都对，看你在不在场：
> - **在场**：开售前 5 分钟打开页面 → 选那个日期 → 下一步 → 开始抢票（方案里能看到具体车次）
> - **不在场**：提前设好预约 → 到点它自己开火。**但标签页必须活到那一刻**（不能关、电脑不能睡）

注意：起售时刻是**服务器时间**。你电脑时钟如果和 12306 差几十秒，界面显示的时刻已经按服务器校准过了，照它走就行。

### 关于票价

方案卡片最前面那个价格是**成人票价**（学生票请自行按 75 折估算，脚本不去猜你的优惠区间）：

- 直达 / 买长乘短：显示你要买的那一段、**按你优先顺序选中的那个席别**的票价
- 中转：显示两段各自的价格和合计，例如 `¥73 + ¥69 = ¥142`

两个要注意的地方：

1. **查价是一趟车一次请求**。所以脚本给它设了预算上限（最多 12 次），并且**连续失败 3 次就整个停掉**——票价只是给你做参考，绝不能因为它把限流额度烧光。没查到价的卡片就是不显示价格，不影响抢票。
2. **抢票过程中不会再查价**。下单 5 步完全不需要价格，所以那个阶段一次多余请求都不发。实际扣款金额以付款页为准。

## 已知限制（都是真的，不是没做完）

| 限制 | 说明 |
|---|---|
| **不能替你付款** | 12306 没有开放支付接口。抢到后脚本只能提醒你，付款必须自己在页面上点。 |
| **接力期间要有人在** | 第 1 段 11:30、第 2 段 17:00，中间几小时。浏览器会把后台标签页限流，脚本会在开火前 5 分钟报警叫你回来——但报警之后需要你处理（付款、重登）。真不想在场，就开「接力期间保持唤醒」+ 让第 2 段走候补 + 手机 12306 免密支付。 |
| **商务座 / 优选一等座不给选座** | 这两种席别在不同车型上的座位字母排布不一样，猜错会让 12306 把整单判成非法参数。界面上会写明原因，由系统自动分配。 |
| **买长乘短要核对经停站** | 靠 `/otn/czxx/queryByTrainNo` 查。这个接口拿不到时脚本会放行并**在日志里警告**——那种情况下请自己确认这趟车真的停你要下的站。 |
| **发车时段筛选没做** | v2 的「发车时间从/到」在这一版没有界面入口（保留在配置里）。需要的话说一声。 |
| **一次「下一步」要 5~12 个请求** | 主站直达 1 + 买长乘短 1 + 中转 1 + 每个不同中转站 1，每个备选日期再算一遍。如果 12306 正好在限流，可能会查不全，过一会儿重点一次。 |

## 跟 v2.1.17 的差别

1. **删掉了整条「联程」链路**（`lcQuery` / `lcConfirmPassenger` 那套）。它参数必须跟 12306 自己的 JS 逐字对齐，一改版就整条失效；而它想解决的问题已经被"两段接力"覆盖。
2. **单个定时改成多个起售点**。起售时间按乘车站算，中转两段分属两个站，时刻通常不同——v2 只能填一个，第二段永远等不到。
3. **中转改成两段接力、半步继续**。v2 是"两段都有票才一起下"，两段起售时间不同时它永远不会触发（第二段开售时第一段早没了）。这条路你之前在日志里见过：`第1段 ✅ ｜ 第2段 ❌` 一直刷，什么都不发生。
4. **界面重做成三步**，方案是查回来的真实车次，你勾选、删除、排序。
5. **接力状态落盘**：抢到半程票之后刷新/跳转，回来还认得自己是谁。
6. **三路唤醒** + 「接力期间保持唤醒」：跨时段等第二段时尽量别被浏览器限流。

## 出问题的排查顺序

1. 面板上点「复制日志」，把面板日志 + 技术日志一起带走。
2. 先看 **面板日志** 最后几行：它说的是人话（"没查到任何方案"、"这条不经过你要下的站"）。
3. 再看 **技术日志** 里的 `[Query]` / `[Plan]` / `[Probe]` 行：
   - `[Probe] fail=3 hot=1` = 那一轮 3 个目的地全被拒；
   - `[Plan] 查询失败` = 那个目的地这一次没查到（会重试）。
4. 常见现象对照：
   - **「还没到起售时间」一直刷** → 正常，脚本在等开火。看「下一场开火」那行。
   - **「12306 没接这次请求」+ 自动变慢** → 退避机制在工作，别停任务，等它缓过来。
   - **「登录已失效」+ 一直响** → 重新登录，切回页面报警就停。
   - **「账号里有未完成订单」** → 去 12306【未完成订单】页把订单支付或取消掉，脚本已自动停止。
